# Spec: paperless-ngx Helm Chart

## Objective

Create a new Helm chart `charts/paperless-ngx` that deploys [Paperless-ngx](https://docs.paperless-ngx.com/) (image `ghcr.io/paperless-ngx/paperless-ngx`) plus its bundled Redis to the author's homelab Kubernetes cluster, built on the [bjw-s-labs common library](https://github.com/bjw-s-labs/helm-charts) (v5.x) — the same convention as `charts/hermes-agent`.

**Target user:** the repo owner (homelab operator), deploying via ArgoCD from [boaboa-iac](https://github.com/boaboacl/boaboa-iac) like the other charts in this repo. The chart replaces a set of raw manifests that currently live in boaboa-iac under `homeserver/k8s/applications/paperless-ngx/resources/` (Deployment, Service, Ingress, Redis Deployment+Service, 3 PVCs).

**Deployment shape (per current live manifests, preserved 1:1 in behavior):** a single paperless-ngx web/document container (port 8000) backed by a bare `redis:7-alpine` instance (port 6379, no persistence), three RWO volumes (`media`, `data`, `export`), PostgreSQL on the CNPG cluster with credentials delivered by a Crossplane-managed connection Secret, and SSO via Authentik OIDC (credentials arrive through pre-created SealedSecrets).

**Data policy (explicit user decision):** the cutover starts from **fresh volumes**. Existing documents are abandoned; observed outcome — Argo pruned the legacy PVCs during cutover (`Delete=false` guards app-deletion cascades, not pruning). The chart therefore always creates its own PVCs — no `existingClaim` adoption path is required.

**Success looks like:** `helm install` of the chart (plus the pre-created SealedSecrets and the Crossplane DB objects) yields a running paperless-ngx reachable over the Traefik ingress, with SSO-only login, no secrets committed to the repo, and fresh PVCs owned by the chart.

## Tech Stack

- Helm 3, chart apiVersion v2
- Dependency: `common` library chart **v5.2.1** from `https://bjw-s-labs.github.io/helm-charts/` (requires Kubernetes >= 1.31; target cluster runs **v1.34.2 (k0s)** — verified for hermes-agent)
- Container images:
  - `ghcr.io/paperless-ngx/paperless-ngx` pinned to **`2.20.15`** (current live tag; recorded as `appVersion`)
  - `redis:7-alpine` (current live tag)
- Verified against the vendored library source (`common-5.2.1.tgz`):
  - `env` entries support native `valueFrom` (used for DB credentials from the Crossplane Secret)
  - `envFrom` supports `secretRef.name`
  - `persistence.<id>.retain: true` renders the `helm.sh/resource-policy: keep` annotation
  - Resource naming: the `main` controller gets the bare fullname (`paperless-ngx`); other controllers, services, and PVCs get `<fullname>-<identifier>`; fullname = release name when it contains the chart name (Argo app name `paperless-ngx` qualifies)

## Commands

```bash
# One-time: add the library chart repo
helm repo add bjw-s https://bjw-s-labs.github.io/helm-charts && helm repo update

# Fetch/pin dependencies (regenerates Chart.lock + dev-only vendored dep under
# charts/paperless-ngx/charts/ — the tgz is NOT committed; CI resolves deps itself)
helm dependency update charts/paperless-ngx

# Lint
helm lint charts/paperless-ngx

# Render (verify output; pipe to kubeconform if installed)
helm template paperless-ngx charts/paperless-ngx

# Negative test for the single-replica guard
helm template paperless-ngx charts/paperless-ngx --set controllers.main.replicas=2  # must fail
```

## Project Structure

```
charts/paperless-ngx/
  Chart.yaml          # app chart, version 0.1.0, appVersion = "2.20.15", dep on common 5.2.1
  Chart.lock          # generated by helm dependency update (committed, like hermes-agent)
  values.yaml         # defaults per "Values design" below
  templates/
    common.yaml       # loader include + envFrom injection + PAPERLESS_REDIS derivation
    guard.yaml        # fails rendering if replicas > 1 (single RWO volume set + single Redis)
  README.md           # usage: secret contract, ports, env vars, migration notes
```

## Values Design (chart contract)

- `controllers.main`: type `deployment`, `strategy: Recreate`, `replicas: 1`
  - container `main`: image `ghcr.io/paperless-ngx/paperless-ngx:2.20.15`, port 8000 `http`
  - `env` (plain values, from current live manifests): `TZ`, `PAPERLESS_URL`, `PAPERLESS_DBENGINE=postgres`, `PAPERLESS_DBHOST` (CNPG rw service FQDN), `PAPERLESS_DBNAME=paperless`, `PAPERLESS_OCR_LANGUAGES=spa`, `PAPERLESS_OCR_LANGUAGE=eng+spa`, `PAPERLESS_APPS=allauth.socialaccount.providers.openid_connect`, `PAPERLESS_DISABLE_REGULAR_LOGIN=true`, `PAPERLESS_REDIRECT_LOGIN_TO_SSO=true`, `PAPERLESS_SOCIAL_ACCOUNT_SYNC_GROUPS=true`
  - `env` with native `valueFrom.secretKeyRef` → Secret `paperless-pgsql-conn` (Crossplane connection Secret), keys `username`/`password` → `PAPERLESS_DBUSER`/`PAPERLESS_DBPASS`
  - `PAPERLESS_REDIS` is NOT set in values — derived in `templates/common.yaml` as `redis://<fullname>-redis:6379` so the chart is release-name-proof
  - `envFrom`: NOT set in values — injected by `templates/common.yaml` from the `secret.existingSecrets` list below
  - probes: httpGet `/` on port 8000; startup probe with generous window (first boot runs migrations), then readiness/liveness — replacing the current `initialDelaySeconds: 60` pattern
  - no resources / securityContext overrides (parity with current live manifests; the image manages its own privilege drop)
- `controllers.redis`: type `deployment`, `replicas: 1`, container `redis` with image `redis:7-alpine` (bare, no persistence, no probes — parity with current live manifests)
- `service.main` → controller `main`, port 8000; `service.redis` → controller `redis`, port 6379
- `ingress.main`: disabled by default; Traefik host + TLS wired via Argo `valuesObject`
- `persistence`: `media` 20Gi, `data` 5Gi, `export` 10Gi — all RWO, `retain: true`, mounted at `/usr/src/paperless/{media,data,export}`
- `secret.existingSecrets`: list of existing Secret names injected wholesale via `envFrom` (default `["paperless-secret-key", "paperless-admin", "paperless-socialaccount"]`; set to `[]` to disable). Chart does NOT create Secrets from values — no secret material in values.yaml, ever
- No `existingClaim` support required (fresh-volume policy)

## Code Style

Match `charts/hermes-agent` exactly: plain 2-space YAML, values grouped by library key (`controllers`, `defaultPodOptions`, `persistence`, `secret`, `service`, `ingress`), useful comments only, Chart.yaml keeps the standard commented boilerplate headers used by sibling charts, `templates/common.yaml` performs pre-loader value mutations before `{{ include "bjw-s.common.loader.all" . }}`.

## Testing Strategy

No unit test framework in this repo — verification is render-based, same as hermes-agent:

- `helm lint` clean
- `helm template` default render checked with grep assertions: correct image tags, all env vars present, `envFrom` referencing all three SealedSecrets, `PAPERLESS_DBUSER/PASS` via `valueFrom`, `PAPERLESS_REDIS` pointing at `<fullname>-redis`, probes on 8000, PVC sizes 20Gi/5Gi/10Gi with `helm.sh/resource-policy: keep`, Services `paperless-ngx-main` (8000) / `paperless-ngx-redis` (6379)
- Negative test: `--set controllers.main.replicas=2` must exit non-zero via guard.yaml
- Variant renders: `secret.existingSecrets=[]` removes `envFrom`; ingress enabled renders Traefik Ingress; release name other than `paperless-ngx` rewrites all resource names + `PAPERLESS_REDIS` consistently

## Boundaries

- Always: run `helm lint` + `helm template` before finishing; keep image tags pinned; commit Chart.lock but never the vendored tgz (root `.gitignore` already covers `**/charts/*.tgz`)
- Ask first: bumping the paperless image tag beyond the current live version, changing volume sizes, adding resource limits
- Never: put secret material in `values.yaml`; create Secrets from chart values; enable the ingress with a placeholder host by default

## Success Criteria

- [x] `helm dependency update charts/paperless-ngx` succeeds; Chart.lock committed, vendored tgz ignored
- [x] `helm lint charts/paperless-ngx` exits 0
