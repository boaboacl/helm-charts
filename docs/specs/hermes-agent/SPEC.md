# Spec: hermes-agent Helm Chart

## Objective

Create a new Helm chart `charts/hermes-agent` that deploys [NousResearch hermes-agent](https://github.com/NousResearch/hermes-agent) (image `nousresearch/hermes-agent`) to the author's homelab Kubernetes cluster, built on the [bjw-s-labs common library](https://github.com/bjw-s-labs/helm-charts) (v5.x).

**Target user:** the repo owner (homelab operator), deploying via Flux/`helm install` like the other charts in this repo.

**Deployment shape (per hermes docker docs):** a single stateful container running `gateway run` under the image's internal s6-overlay supervision, with a persistent volume at `/opt/data` (all state: `.env`, `config.yaml`, `SOUL.md`, sessions, memories, skills, SQLite `state.db`), the supervised web dashboard enabled (`HERMES_DASHBOARD=1`, port 9119), and the OpenAI-compatible API server surface available (port 8642).

**Success looks like:** `helm install` of the chart (plus one Secret with credentials) yields a running hermes gateway reachable on the dashboard, surviving pod restarts with state intact, with no secrets committed to the repo.

## Tech Stack

- Helm 3, chart apiVersion v2
- Dependency: `common` library chart **v5.2.1** from `https://bjw-s-labs.github.io/helm-charts/` (requires Kubernetes >= 1.31; target cluster runs **v1.34.2 (k0s)** — verified)
- Container image: `nousresearch/hermes-agent` pinned to the stable CalVer tag **`v2026.9.24`** (latest stable as of spec time; multi-arch amd64/arm64) — recorded as `appVersion`
- NOTE: this is the first chart in this repo using bjw-s common; the existing 4 charts use TrueCharts common. Different values schema — do not mix conventions.

## Commands

```bash
# One-time: add the library chart repo
helm repo add bjw-s https://bjw-s-labs.github.io/helm-charts && helm repo update

# Fetch/pin dependencies (regenerates Chart.lock + dev-only vendored dep under
# charts/hermes-agent/charts/ — the tgz is NOT committed; CI resolves deps itself)
helm dependency update charts/hermes-agent

# Lint
helm lint charts/hermes-agent

# Render (verify output; pipe to kubeconform if installed)
helm template hermes-agent charts/hermes-agent

# Deploy (with the credentials secret created out-of-band)
kubectl create ns hermes
kubectl -n hermes create secret generic hermes-agent-env --from-env-file=hermes.env
helm install hermes charts/hermes-agent -n hermes --set secret.existingSecret=hermes-agent-env
```

```

```

## Values Design (chart contract)

- `image`: `nousresearch/hermes-agent`, tag = appVersion, `pullPolicy: IfNotPresent`
- `controllers.main`: type `deployment`, `strategy: Recreate`, `replicas: 1`
  - container `main`: `args: ["gateway", "run"]` (entrypoint dispatcher routes this to `hermes gateway run`); NEVER override command/entrypoint (s6 must own PID 1 semantics)
  - `env`: `HERMES_DASHBOARD=1`, `HERMES_DASHBOARD_HOST=0.0.0.0`, `API_SERVER_ENABLED=true`, `API_SERVER_HOST=0.0.0.0`, `TZ` from values
  - `envFrom` the credentials Secret (see `secret` below)
  - probes: tcp on 9119 (liveness/readiness/startup, generous startup timeout) — overridable in values
- `defaultPodOptions.securityContext`: `runAsUser: 0`, `runAsGroup: 0`, `readOnlyRootFilesystem: false` (stage2 chowns the volume as root, then s6 drops to `hermes` UID 10000; matches repo convention)
- `service.main` → port 9119 (dashboard); `service.api` → port 8642 (OpenAI-compatible API)
- `ingress.main`: disabled by default, opt-in
- `persistence.data`: PVC (ReadWriteOnce, default 8Gi, `retain: true`) mounted at `/opt/data`
- `secret.existingSecret`: name of a pre-created Secret consumed via `envFrom` (default `""`); chart does NOT create secrets from values — no credentials in values.yaml, ever
- `resources`: requests cpu 1 / memory 1Gi, limits cpu 2 / memory 4Gi (per upstream recommended minimums; browser tools need headroom)

## Code Style

Match the repo's existing charts: plain 2-space YAML, values alphabetized-ish within sections, no trailing comments beyond useful ones. Chart.yaml keeps the standard commented boilerplate headers used by sibling charts. One new deviation: bjw-s values schema instead of TrueCharts `tc.v1.common.loader.all`.

```yaml
# values.yaml (excerpt — the style to follow)
controllers:
  main:
    strategy: Recreate
    replicas: 1
    containers:
      main:
        args: ["gateway", "run"]
        env:
          HERMES_DASHBOARD: "1"
```

## Testing Strategy

No test framework exists in this repo; keep verification lightweight and manual:

1. `helm dependency update charts/hermes-agent` succeeds and pins common 5.2.1
2. `helm lint charts/hermes-agent` passes
3. `helm template` renders: Deployment (Recreate, 1 replica, correct args/env), both Services, PVC, envFrom → Secret reference; and **fails loudly** when `controllers.main.replicas` is set > 1
4. `helm template -f` with a dashboard-disabled values file renders without dashboard env
5. Manual: deploy to the homelab cluster, confirm dashboard loads behind basic auth, `kubectl exec` shows `hermes gateway status` healthy, restart pod → state survives
6. CI: existing chart-releaser workflow publishes on merge; do NOT modify CI without asking

## Boundaries

- **Always:** pin image by X.Y.Z tag; hard-enforce single replica; mount exactly one PVC at `/opt/data`; keep dashboard basic-auth vars in the Secret (dashboard fails closed on non-loopback binds without an auth provider); commit Chart.lock (pins library digest; cheshirecat precedent) but never commit the vendored `charts/hermes-agent/charts/*.tgz`; bump chart `version` on every change (chart-releaser only publishes version changes); run lint + template before considering work done
- **Ask first:** modifying `.github/workflows/*`; changing shared repo conventions; adding a lint/test CI job; bumping the common library major version
- **Never:** commit real API keys/tokens to values.yaml or README; override the image entrypoint/command; enable `HERMES_DASHBOARD_INSECURE` (deprecated no-op anyway); run >1 replica against the data volume; share `/opt/data` between two gateways

## Success Criteria

- [x] `helm lint` + `helm template` clean with defaults; render includes Deployment(args: gateway run), Services 9119/8642, PVC at /opt/data, envFrom Secret
- [x] Setting replicas > 1 makes `helm template` fail with an explanatory error
- [x] With `secret.existingSecret` pointing at a Secret containing `HERMES_DASHBOARD_BASIC_AUTH_USERNAME`/`_PASSWORD` and a model-provider key, the deployed pod reaches Running and the dashboard authenticates
- [x] Pod restart (delete pod) preserves sessions/config (PVC `retain`)
- [x] README documents the env-only bootstrap: required vars (>=1 model provider key, dashboard basic-auth trio), optional vars (chat platform tokens, `API_SERVER_KEY` >= 8 chars), secret creation command
- [x] No secret material anywhere in the chart or repo

**Outcome (2026-10-04):** all criteria met. Deployed via ArgoCD from boaboa-iac (SealedSecret `hermes-agent-env`, namespace `applications`, traefik ingress `hermes.k8s.boaboa.org`); gateway s6-supervised, auth gate verified fail-closed, restart persistence verified. Model provider in production: z.ai (GLM) — first-class `zai` provider, coding-plan endpoint auto-detected.
